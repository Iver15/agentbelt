# Прокси для Claude Code и Codex

Небольшой HTTP-прокси на VPS меняет сетевой маршрут до API агентов. Он полезен, когда прямое соединение недоступно или нестабильно. Эта инструкция описывает вариант из исходного проекта: gost в Docker, настройку CLI и ограничение доступа к прокси.

Прокси меняет точку выхода трафика. Учётная запись, оплата и условия использования API остаются прежними; проверьте применимость условий провайдера к своему аккаунту. Примеры ниже содержат вымышленные адреса и пароли. Указанные версии и команды взяты из проекта; это не проверка актуальных правил провайдеров или доступности конкретного VPS.

## 1. Сервер

В исходном примере используется VPS с Ubuntu 22.04/24.04 и установленным Docker. Для небольшого прокси можно начать с 1 vCPU и 1 ГБ RAM; необходимый объём трафика зависит от вашей нагрузки.

[gost](https://github.com/ginuerzh/gost) v2 поддерживает HTTP CONNECT и авторизацию по паролю. TLS-соединение агента проходит через CONNECT до API; содержимое такого соединения прокси не расшифровывает.

```bash
# Файл учётных данных: одна строка «пользователь пароль».
# Пароль не помещается в аргументы запуска Docker.
mkdir -p /opt/gost && umask 077
echo "me $(openssl rand -base64 24 | tr -d '/+=')" > /opt/gost/secrets.txt

docker run -d --name gost-http --restart unless-stopped \
  -p 48921:48921 \
  -v /opt/gost/secrets.txt:/secrets.txt:ro \
  --log-opt max-size=10m --log-opt max-file=3 \
  ginuerzh/gost:2.11.5 -L "http://:48921?secrets=/secrets.txt"
```

- Закрепите версию образа: `latest` может измениться без вашего участия.
- Ограничьте размер журналов через `max-size` и `max-file`, чтобы они не заполнили диск.
- Произвольный высокий порт уменьшает шум от сканирования, но не заменяет авторизацию и сетевые ограничения.

Проверка с вашего компьютера; замените `PASSWORD` и `SERVER` собственными значениями. URL прокси передаётся curl через stdin:

```bash
printf 'proxy = "http://me:PASSWORD@SERVER:48921"\nurl = "https://api.anthropic.com/v1/models"\n' \
  | curl -s -o /dev/null -w '%{http_code}\n' -K -
```

HTTP 401 означает, что запрос дошёл до API, но требует авторизации. HTTP 403 — отказ в доступе; причина может быть региональной или иной. Отсутствие HTTP-ответа указывает на проблему маршрута, соединения, прокси или TLS. Эта проверка не подтверждает успешную работу агента с вашим аккаунтом.

## 2. Агенты

Один запуск **Claude Code** через прокси:

```bash
HTTPS_PROXY=http://me:PASSWORD@SERVER:48921 claude
```

Для последующих запусков Claude параметр можно добавить в `~/.claude/settings.json`:

```json
{ "env": { "HTTPS_PROXY": "http://me:PASSWORD@SERVER:48921" } }
```

Один запуск **Codex**:

```bash
HTTPS_PROXY=http://me:PASSWORD@SERVER:48921 codex
```

В логике agentbelt проверка Codex с авторизацией ChatGPT направляется к `chatgpt.com`, с API-ключом — к `api.openai.com`. Проверьте доступность используемого адреса через свой прокси.

Через интерфейс agentbelt:

1. Откройте **◆ Подключения** или ссылку **подключения** во вкладке «Сессии».
2. В **Добавить прокси** задайте название и URL либо заполните поля протокола, адреса, порта, логина и пароля. Нажмите **Проверить и добавить**.
3. Выберите Claude Code или Codex и нужный маршрут. **Использовать по умолчанию** сохраняет его для новых сессий выбранного агента; после добавления также можно назначить маршруты обоим агентам в блоке **После добавления**.
4. **Запустить … через …** выполняет разовый запуск в текущем каталоге, **Проверить** обновляет результаты API. Статусы Claude и Codex независимы.
5. В **Готовность запуска** проверьте соединение с iTerm2, наличие CLI и каталог. **Обновить** проверяет CLI в новой оболочке без запуска агента. При пустом назначении по умолчанию маршрут нужно выбрать явно.
6. **Изменить** в выбранной карточке сохраняет текущий пароль без повторного ввода, позволяет явно заменить/удалить его и обновляет назначения при переименовании. **Дублировать** создаёт копию без смены назначений.
7. **Удалить** требует выбрать другой маршрут или **напрямую** для каждого назначенного агента; список учитывает pi/omp. Без явных замен удаление не сохраняется. Для серверов, роутера и назначения pi/omp используйте **Настройки сети**. Старый сетевой блок во вкладке «Действия агента» сохраняет команды копирования и запуска.

Во вкладке «Подключения» проверки выполняются по запросу пользователя; экран также может использовать уже полученный результат старого сетевого блока. Старый блок обновляет свой кэш примерно раз в минуту при обращениях. Для переключения можно хранить несколько маршрутов; уже запущенный агент не меняет прокси автоматически. Проверка доступности выполняется без входа в аккаунт. Подробности — в [справочнике настроек](configuration.ru.md).

## 3. Ограничение доступа

Доступный всему интернету прокси может быть использован посторонними. В исходном проекте предложены следующие меры:

1. **Авторизация по паролю.** Используйте длинный случайный пароль, храните его в файле учётных данных и меняйте после утечки в журнал, переписку или снимок экрана.
2. **Список разрешённых адресов.** Если ваши IP стабильны, ограничьте доступ к порту. Пример для UFW:

   ```bash
   ufw default deny incoming
   ufw allow 22/tcp
   ufw allow from YOUR.IP.ADDR.ESS to any port 48921 proto tcp
   ufw enable
   ```

   Перед включением убедитесь, что разрешён фактический порт вашего SSH. Опубликованные Docker-порты могут обходить обычные правила UFW: настройте фильтрацию в `DOCKER-USER` либо привязку к закрытому адресу.
3. **Публикация внутри туннеля.** При настроенном WireGuard/AmneziaWG можно привязать порт к адресу туннеля: `-p 10.8.0.1:48921:48921`. Тогда прокси не слушает публичный интерфейс. Это также защищает передаваемые по обычному HTTP учётные данные прокси от наблюдения на внешнем участке сети.

Дополнительно контролируйте место на диске, память и доступность порта. Для SSH применяйте вход по ключам и подходящие правила ограничения попыток входа. Если внешний маршрут до прокси нестабилен, рассмотрите передачу трафика к нему через уже настроенный туннель.

## 4. Что agentbelt делает с секретами прокси

- Список хранится только в `~/.config/agentbelt/config.json`, с правами `0600`; файл исключён из Git.
- При сетевой проверке URL передаётся curl через stdin.
- URL из списка прокси маскируется в настройках; неизменённая строка с `***` сохраняет исходный пароль.
- **⧉ копировать** помещает полную команду, включая пароль, прямо в буфер обмена.
- Лента действий маскирует распространённые формы паролей и токенов по регулярному выражению.

Произвольные `prefix`/`flags` не имеют той же серверной очистки, что список прокси. Не помещайте туда секреты, если можете использовать отдельный `proxies`; см. [границы защиты](configuration.ru.md#обращение-с-секретами).
