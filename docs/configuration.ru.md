# Настройки agentbelt

Основной путь: `~/.config/agentbelt/config.json`. Откройте **◆ Сессии → ⚙ настройки** для редактирования через интерфейс и нажмите **Сохранить**. Настройки сохраняются атомарно с правами `0600`. Локальная конфигурация исключена из Git.

Описание включает русскую локализацию и первый этап экрана «Подключения»; [руководство пользователя](../README.md).

## Минимальная конфигурация без демонстрационной сети

Пример для новой установки или осознанной замены настроек. Перед заменой существующего файла сохраните собственные параметры отдельно.

```json
{
  "port": 47811,
  "title_prefix": "◆ ",
  "tabs": {"git": true, "agent": true, "connections": true, "sessions": true, "settings": false},
  "open_in": "window",
  "agents": {
    "claude": {"prefix": "", "flags": "", "proxy": "direct", "skip_permissions": false},
    "codex": {"prefix": "", "flags": "", "proxy": "direct"},
    "pi": {"prefix": "", "flags": "", "proxy": "direct"},
    "omp": {"prefix": "", "flags": "", "proxy": "direct"}
  },
  "proxies": [],
  "servers": [],
  "keenetic": {},
  "repo_checks": [],
  "auto_show_toolbelt": true,
  "autosave": true,
  "onboarded": false
}
```

`direct` явно удаляет переменные окружения прокси для запускаемого CLI. При пустом `proxy` и пустом `prefix` CLI наследует окружение новой командной оболочки, включая заданные в нём прокси.

## Общие параметры

| Ключ | Встроенное значение | Назначение |
|---|---|---|
| `port` | `47811` | Порт HTTP-сервера на `127.0.0.1`; меняется вручную, затем нужен перезапуск |
| `title_prefix` | `"◆ "` | Префикс названий инструментов iTerm2 |
| `tabs` | git/agent/connections/sessions включены, settings выключена | Регистрация отдельных вкладок; настройки всё равно доступны по ⚙ |
| `open_in` | `"window"` | Новое окно; `"tab"` — вкладка текущего окна, если оно есть |
| `auto_show_toolbelt` | `true` | Показывать панель при первом обнаружении окна; после ручного скрытия в этом окне не включать снова в том же процессе |
| `autosave` | `true` | Автоснимки при изменении структуры и наличии Claude-сессии |
| `onboarded` | `false` | Отметка о просмотре вводной инструкции, кнопка «Понятно» |
| `repo_checks` | `[]` | Команды пользовательских проверок для Git-панели |
| `proxies`, `servers` | `[]` | Необязательные списки сетевых маршрутов и серверов |
| `keenetic` | `{}` | Необязательные параметры RCI роутера |

`load_config()` дополняет пользовательские параметры встроенными значениями; вложенные настройки агентов объединяются. Значения из `config.example.json` отличаются от встроенных значений по умолчанию: в примере есть демонстрационные адреса и выбранный прокси Claude.

Сохранение `tabs` или `title_prefix` через UI завершает сервис, после чего `launchd` перезапускает его с новыми регистрациями. Другие поддерживаемые UI-параметры применяются без перезапуска. При ручном редактировании файла перезапустите сервис, чтобы обновить параметры в памяти:

```bash
launchctl kickstart -k "gui/$(id -u)/dev.agentbelt"
```

## Настройки запуска агентов

Для `claude`, `codex`, `pi`, `omp` доступны `prefix`, `flags`, `proxy`; для Claude дополнительно `skip_permissions`.

| Параметр | Поведение |
|---|---|
| `prefix` | Текст перед командой CLI, например `ENV_NAME=value`; используется при пустом `proxy` |
| `flags` | Текст после команды CLI и ID сессии |
| `proxy` | Имя из `proxies`, `direct` либо пустая строка; непустой выбор полностью заменяет prefix |
| `skip_permissions` | Исходное значение для флажка «Claude без запросов разрешений» и запусков Claude из сетевого блока |

Команда отправляется в новую командную оболочку iTerm2 после ожидания его готовности. Сервис подставляет каталог с экранированием для командной оболочки и ID, но `prefix` и `flags` — доверенный текст для командной оболочки. Указывайте там только собственные параметры. Выбор во вкладке «Сессии» может сохраняться локально в браузерной панели и перекрывать `open_in`/`skip_permissions` из файла.

| CLI | Новая сессия | Возобновление |
|---|---|---|
| Claude Code | `claude` | `claude --resume <id>` |
| Codex | `codex` | `codex resume <id>` |
| pi | `pi` | `pi --session <id>` |
| omp | `omp --config <путь>/resources/omp-new-session.yml` | `omp -r <id>` |

К этим командам добавляются выбранные prefix/proxy и flags. Для нового omp разовый `--config` добавляется после пользовательских flags; файл задаёт `autoResume: false`. Для Claude `--dangerously-skip-permissions` удаляется из `flags` и добавляется по флажку, чтобы режим контролировался одним переключателем.

Системные команды сервиса выполняются с PATH, дополненным `/opt/homebrew/bin`, `/usr/local/bin` и системными каталогами. CLI запускается в новой пользовательской командной оболочке: наличие Codex в NVM-пути у текущего терминала само по себе не доказывает его доступность в новом окне iTerm2. Проверьте `command -v codex` именно там.

## Прокси, серверы и Keenetic

Для Claude и Codex откройте **◆ Подключения → Добавить прокси**. Режим **Поля** принимает протокол HTTP/HTTPS, адрес, порт и необязательные логин с паролем. Режим **URL** принимает полный URL вида `scheme://[user:pass@]host:port`. Валидатор принимает `http`, `https`, `socks5`, `socks5h`; возможность использования конкретного типа прокси самим CLI проверяйте его запуском. Имя `direct` зарезервировано.

```json
{
  "proxies": [{"name": "example", "url": "http://user:CHANGE_ME@proxy.example.com:3128"}],
  "servers": [{"name": "Пример SSH-сервера", "host": "server.example.com", "port": 22}],
  "keenetic": {}
}
```

Это фрагмент настроек с вымышленными значениями. В «Подключениях» нажмите **Проверить и добавить**, затем выберите агента, маршрут и **Использовать по умолчанию**. После добавления блок **После добавления** позволяет назначить оба маршрута сразу. Даже недоступный сейчас прокси можно сохранить; некорректные параметры отвергаются. Для редактирования, удаления и настройки pi/omp используйте **Настройки → Сеть → Прокси** и **Прокси новых сессий (заменяет префикс)** у агента. Уже запущенные процессы продолжат использовать прежнее окружение.

В **Серверы → + сервер** задайте имя, сетевой hostname/IP и порт. По умолчанию читается SSH-приветствие. Снимите **приветствие** для портов, не отдающих SSH-приветствие. Это ping и TCP-проверка, а не SSH-вход; `host` должен разрешаться как сетевое имя, SSH-алиас из `~/.ssh/config` не обрабатывается.

Для блока **Роутер Keenetic** задайте адрес, логин и пароль. Проверка включается при наличии пароля: сервис читает состояние WireGuard и цепочки маршрутов доменных групп через RCI. Пустой адрес отключает интеграцию; пустой пароль при сохранении сохраняет прежний пароль. Маршрутизация роутера этим интерфейсом не изменяется.

### Что означают сетевые индикаторы

В «Подключениях» результаты обновляются по кнопке **Проверить** или **Проверить и добавить**, с временем последней проверки и отдельными статусами Claude/Codex. HTTP 401 означает доступность API, 407 — требование авторизации прокси, 403 — отказ, 429 — ограничение запросов. В старом сетевом блоке прокси проверяются примерно раз в 60 секунд, Keenetic — раз в 15 секунд. Это TTL кэша: обновление запускается запросом панели, а не отдельным расписанием при закрытой панели. Запросы не используют API-ключи агентов.

| Индикатор | Значение |
|---|---|
| Число миллисекунд, зелёный | HTTP 200–399 или 401; доступность API без подтверждения входа |
| `403` | Предупреждение о запрете доступа; сам код не доказывает региональную причину |
| `407`, `429` | Требование авторизации прокси либо ограничение запросов; предупреждение |
| `недоступен` | Нет HTTP-ответа; возможны проблемы DNS, соединения, прокси или TLS |
| `5xx` | Ошибка сервера/маршрута, предупреждение |
| `открыт, без приветствия` | TCP-соединение установлено, SSH-приветствие не получено |

Зелёный статус подтверждает доступность проверяемого адреса, но не авторизацию, доступ к модели или успешную работу агента. Прокси получает общий зелёный маркер, когда доступными признаны все три колонки: `claude`, `codex`, `openai`.

Цели прописаны в коде: Anthropic `/v1/models`, OpenAI `/v1/models`; для Codex при `auth_mode: chatgpt` в `~/.codex/auth.json` используется `chatgpt.com/backend-api/codex/models`. Пользовательские базовые URL API здесь не учитываются. Текущий маршрут в заголовке **Этот Claude** читается из окружения процесса Claude активной области, а не из окружения Codex.

### Обращение с секретами

- Экран «Подключения» получает только имя, адрес с портом и результаты проверки; URL с учётными данными, `prefix` и `flags` в его ответ состояния не включаются.
- Пароли URL из `proxies` маскируются в ответе настроек; неизменённая строка с `***` сохраняет исходный пароль.
- Пароль Keenetic в ответ не включается; передаётся только признак наличия.
- `prefix` и `flags` не имеют такой же серверной очистки: парольное поле скрывает текст визуально, но не удаляет его из JSON-ответа. Для прокси предпочтителен отдельный список `proxies`.
- Для проверки через curl URL прокси передаётся через stdin; **⧉ копировать** отправляет полную строку прямо в буфер обмена.
- Лента Claude маскирует распространённые формы токенов и паролей по регулярному выражению; это не универсальная очистка всех приватных данных.

HTTP-сервис доступен только на локальном интерфейсе. Не публикуйте его порт через туннель или внешний обратный прокси: чтение локальных маршрутов не требует отдельной авторизации и раскрывает рабочие данные. Заголовок `X-Toolbelt: 1` ограничивает браузерные запросы на изменение состояния, но не защищает от других локальных процессов.

## Проверки репозитория

В поле **Проверки репозитория** введите JSON-массив:

```json
[
  {
    "name": "Контейнеры",
    "file": "docker-compose.yml",
    "cmd": ["docker", "compose", "ps"],
    "timeout": 25,
    "max_lines": 6
  }
]
```

Если `file` указан и существует относительно корня репозитория, запускается `cmd`; без `file` проверка запускается для любого Git-репозитория. Команда выполняется в корне проекта, результат кэшируется примерно на 45 секунд. Код выхода 0 отображается зелёным, остальные — красным; таймаут возвращает код 124.

Строка `cmd` разбирается через `shlex.split` и запускается **без командной оболочки**: конвейеры, `&&`, подстановка переменных и перенаправления не работают сами по себе. Массив аргументов удобнее для точного задания команды. Это автоматически повторяемые проверки: выбирайте команды без нежелательных побочных эффектов.

## Каталоги и переменные окружения

| Переменная | Назначение |
|---|---|
| `AGENTBELT_HOME` | Каталог конфигурации/кэша; поддерживается сервисом и установщиком |
| `ITERM_TOOLBELT_HOME` | Старый резервный параметр для каталога конфигурации в сервисе; установщик использует AGENTBELT_HOME |
| `ITERMSNAP_HOME` | Основа каталога снимков; сервис добавляет `/snaps`, по умолчанию `~/.config/itermsnap` |
| `SHELL` | Командная оболочка, готовность которой ожидается перед отправкой команды; установщик сохраняет текущее значение, по умолчанию `/bin/zsh` |

Пример установки в другой каталог конфигурации: `AGENTBELT_HOME="$HOME/.config/agentbelt-alt" ./install.sh`. Метка LaunchAgent остаётся `dev.agentbelt`: это перенос одной установки, а не создание независимого второго сервиса.

Установщик не добавляет `ITERMSNAP_HOME` в plist. Чтобы менять каталог снимков для LaunchAgent, эту переменную нужно явно добавить в его `EnvironmentVariables`; повторная установка переписывает plist. Каталоги историй агентов привязаны в коде к `~/.claude`, `~/.codex`, `~/.pi`, `~/.omp`; отдельных настроек путей для них нет.
